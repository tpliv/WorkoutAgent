# Data

The training log and the live state of the program. Everything here except
`raw/` is committed so agents in later sessions can read it.

| File | What it is |
|---|---|
| `history.csv` | Normalized set-level log, one row per set (format in `tools/README.md`). Loads stay in kg, exactly as the Hevy API returns them; the tools convert to pounds. Filled by `tools/hevy_pull.py` from the Hevy API or by `tools/hevy_csv_import.py` from an app export. |
| `history-summary.md` | Per-exercise e1RM history and the proposed starting loads, generated by `tools/analyze_history.py`. |
| `tracks.json` | In pounds. The six progression tracks: planned next heavy load, last lifted load, rep target, miss counter, last exposure, e1RM history, plus the pointer, block week and accessory loads. Rewritten by `tools/update_tracks.py`; read by `tools/hevy_push_routines.py`. |
| `track-state.md` | Narrative companion to `tracks.json` with the same table (regenerated between the markers) and notes on each lift. |
| `track-log.md` | Append-only record of every decision `update_tracks.py` made and why. |
| `body-composition.md` | Body-composition baseline, population comparison, calorie and macro plan, adjustment rules, and the scan log. Updated by hand after each scan. |
| `hevy-exercise-map.json` | Program exercise name to Hevy exercise template id, filled by `hevy_push_routines.py --resolve`. Edit by hand when a match is wrong. |
| `exercise-muscles.json` | Hevy exercise title to primary and secondary muscle groups and exercise type, from Hevy's exercise templates (`tools/build_dashboard.py --refresh-muscles`). Used for sets per muscle and tonnage on the dashboard. |
| `hevy-state.json` | Hevy folder id, routine ids per slot, and the timestamp of the last pull. |
| `raw/` | Raw API JSON and app exports. Gitignored. |

The API key is never written here. It lives only in the `HEVY_API_KEY`
environment variable.
